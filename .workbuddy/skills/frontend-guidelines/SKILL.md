# 前端设计规则

适用对象：手机优先的原生 HTML/CSS/JS 静态页面（无框架、无构建步骤）。
规则来源：WG课程表项目 `css/base.css`、`css/pages.css` 中已实测确认的取值（2026-09-30 整理）。
不适用：React/Vue 等有构建步骤的项目、以桌面端为主的后台系统。

## 怎么用这份规则

1. 开工前读完本文件，别边改边看。
2. 逐条核对，每条给三样东西：**规则 → 实际值 → 通过与否**。不给「我觉得不够好」，只给「实测不到标」。
3. 核对结果写成一份记录（哪条不过、当时是多少、改成多少），这份记录就是「调用过一次」的证据。
4. 数字对不上的地方，先量再改；量不了的（好不好看）交给人眼判断。

## 一、页面层级

- 每个页面**只有一个主标题**（`<h1>`，通常就是页头里的产品名）。区块标题用 `<h2>`/段落，不重复出一级标题。
- 页头标题 16px、字重 600——不要大过正文信息太多，产品名不是主角。
- **区块之间靠间距分组，不靠加边框区分**：区块之间 16px，同一组内卡片之间 12px。两级节奏要拉开，否则卡片会糊成一块。
- 同一张卡片内所有元素左边缘对齐在同一条基准线上。给单个元素加额外左内边距（如 4px）会制造出 16px / 20px 两条基准线，属于缺陷。
- 核对：数 `<h1>` 个数（应为 1）；量区块间距 16px、卡片间距 12px；量卡片内各元素左边缘是否重合。

## 二、颜色与字体

- **字号只有四档：12 / 14 / 16 / 20px**。出现 11px、13px、18px 这类值就是漏网硬编码，收回档位里。
- 正文与次要信息 14px，页面主文字 16px，区块主标题 ≥20px。
- **产品核心信息不得用最小档**。反面例子：把「第几节 · 在哪 · 谁上」写成 12px 浅灰——用户最需要读的一行成了最小最淡的，层级做反了。
- 文字灰分两档，职责不能混：
  - 承载信息的次要文字：`#5f6b7a`（实测在所有用到的底色上 ≥4.6:1）；
  - 装饰级灰 `#8a9099`：**只允许给 `:disabled` 的文字用**，不得承载信息。
- **正文与背景的对比度 ≥4.5:1（WCAG AA）**。浅灰字不要放在白底或浅底上。
- 主色只用一支（示例 `#2a63d6`）：白底 5.45:1、浅蓝底 `#eaf1fe` 上 4.80:1。调主色时必须连它压的底色一起算，只测白底会漏。
- 核对：列出页面所有字号去重，应只有四档；用对比度公式实测（不目测）。

## 三、卡片与按钮

- 卡片内边距分两档：**通用卡片**（成块的白色区域）16px；**列表里的紧凑卡片**（如一条课程、一条记录）上下 12px、左右 16px。圆角 12px，小卡片 8px。
- 相邻卡片间距 12px（区块之间 16px，见第一节——两级节奏要拉开）。
- **按钮至少要有四种状态**：默认 / 悬停 `:hover` / 按下 `:active` / 禁用 `:disabled`，另加键盘焦点 `:focus-visible`。这是本项目实测确认的下限，只有「默认 + 悬停」不算合格。
- 禁用态不能只把颜色调浅：用**底色 + 边框 + `cursor: not-allowed`** 三者共同表达「不能点」，文字色可以压到最浅。
- 按钮状态切换要有过渡（≤0.2s），没有过渡就是「跳」的一下。
- 危险操作单独一支警示色（示例 `#b3352b` 文字 + `#f0b4ae` 边框），不与主色混用。
- 空状态、错误状态、禁用状态三者视觉上要能一眼分开：含义不同就不能长得一样（典型错误：把「读取失败」画成「还没有数据」）。
- **空状态/错误状态的说明文字必须比标题多给一条信息**，不能与标题同义反复。反例：标题「今天没有课」+ 说明「今天没有排课」——等于没说；正解是补「那哪天有」这类可行动信息（如「今天没有排课，本周周三、周四还有课」）。判断标准：把标题遮住，说明文字单看还能不能让人知道自己该干什么。
- **过程状态（加载中 / 失败）要能被人看到才算做过**。若数据源是同步瞬时返回（如 mock 数据），这两个状态永远不触发——验收时必须用「临时改数据读取函数再改回」的办法手工触发一次，并留下截图。改回后要 `grep` 验证零残留。
- 核对：`grep -cE ':hover|:active|:focus|:disabled' css/*.css`，返回 0 就是最大的问题；再逐个按钮点一遍，确认四态都看得见；把每个空状态的标题与说明并排读一遍，检查有没有同义反复。

## 四、移动端

- **360px 宽度下不能出现横向滚动**：`body { overflow-x: hidden }`，同时给内容设最大宽（示例 720px，桌面端居中一列不铺满）。
- 宽内容（≥7 列的网格、宽表格）**自己内部滚动**（`overflow-x: auto`），不许把整页撑宽。
- flex 子项里放长文本要加 `min-width: 0`，否则长内容会把父容器顶破。
- 导航与切换器在小屏要么等宽平分、要么折叠，不能溢出。
- 页头用 `position: sticky` 固定在顶部；**不要用 `fixed` 贴死视口底边**——任务栏、手机手势条会把它挡住。
- 小屏上首屏要能直接看到核心信息（本产品的「下一节课」），不需要先横滑。
- 核对：浏览器宽度拉到 360px，看有没有横向滚动条；逐个宽元素确认是内部滚动。

## 五、修改前

- **先列具体问题清单，再逐个修，一次只改一个**。每条问题写成「哪里 + 现在是多少 + 应该是多少」，写成能核对的形式。
- 改动范围之外的问题只记录、不动手。想顺手优化的，先问一句。
- 样式改动尽量只动 CSS，不碰 HTML / JS——不动结构才能证明「功能零变化」。
- 先量后改：涉及对比度、尺寸的，先测出当前值，改完再测一次，两次数字都要留档。
- 核对：改之前先交出问题清单，等人确认再动手。

## 六、修改后

- **桌面宽度（≥720px）与手机宽度（360px）各看一遍**，两边都要过。
- 确认交互没有因为改样式而失效：视图切换、输入、按钮点击、键盘 Tab 走一遍都正常。
- 纯样式改动要能证明「功能零变化」：改动前后各取一次 DOM 快照，**去掉时间戳与端口后比对 md5**，相同即零行为变化（快照脚本见同名工作流工具）。
- 视觉效果只能靠人眼看：脚本能证明「没坏」，不能证明「好看」。
- 核对：两种宽度各留一张截图；快照 md5 一致；改动文件清单交出来。

## 七、可访问性

- 对比度：承载信息的文字 ≥4.5:1；大字号（≥24px，或 ≥18.66px 粗体）≥3:1。灰字压灰底是最常踩的一条。
- 键盘可达：每个可交互元素按 Tab 都能走到，且**焦点可见**——`:focus-visible` 给 `outline: 2px solid` + `outline-offset: 2px`。全站没有任何焦点样式等于键盘用户看不见自己在哪。
- 语义与标签：输入控件必须有关联的 `<label>`（或 `aria-label`）；数量、状态这类会变化的结果用 `aria-live` 播报；图标优先用 CSS 画或给替代文本。
- 减少动效：`@media (prefers-reduced-motion: reduce)` 下关闭动画与过渡，**留静止状态**（转圈变静止的圈），不要留空白。
- 触摸目标：可点区域 ≥40×40px，移动端表单控件建议 ≥44px 高。
- 颜色不作为唯一信息载体：状态不能只靠颜色区分，要带文字或图标（如「已结束」标签而非只有灰点）。
- 核对：Tab 键走一遍看焦点；系统开启「减少动态效果」再看一遍；量触摸目标尺寸；量对比度。
