# Day 28 · 演示提纲（3–5 分钟）

> 用法：对照公网页面边讲边点。每节标了大致用时，总长约 4 分钟。

## 0. 开场一句话（15 秒）

「这是一个大学生课表工具——把教务系统导出的课表文件变成手机日历，28 天，从一个念头到一个能用的线上产品。」

## 1. 用户问题（30 秒）

- 课表锁在教务系统里：截图不方便看、想放进手机日历得手敲几十门课。
- 换个浏览器、换个 App 课表就「丢」了，多设备不同步。
- 室友想要？把账号密码给他不现实——需要一个不靠账号的轻量共享方式。

## 2. 核心流程（60 秒，现场演示主线）

1. 打开公网地址 → 入口页「创建课表」生成 6 位口令（房间号模式：口令就是房间号+钥匙）。
2. 导入页：选教务导出的 `.xls` 文件 → 本地解析 → 预览 29 门课、跳过无效行 → 二次确认 → 上传替换。
3. 首页：今日视图（当前周数、下一节课、每节课「已结束/正在上课/未开始」状态）→ 切到周视图 → 换周看任意一周。
4. 设置页：滚筒选时改作息 → 保存上云 → 导出 `.ics`，导入手机日历。
5. 把带 `?code=` 的链接发给室友 → 他打开就是同一张课表（隔离：各口令互不可见）。

## 3. 提示词改写（45 秒，讲 28 天里真实的变化）

对比讲三个真实演变：

| 早期 | 后来 |
|---|---|
| 「帮我做一个课表页面」（一句带过，AI 自由发挥） | 每天一份任务清单：板块顺序、完成标准、今日不做、卡住降级预案——范围和验收标准都写死 |
| 出了问题就问「怎么办」 | 把教训固化成规则写进 AGENTS.md：说「做完」必须给可验证证据；先改接口契约再写代码；测试不过不进下一步 |
| 功能描述靠嘴 | 反馈带复现路径：「微信里调好的设置，换系统浏览器打开就没了」→ 一句话定位到 localStorage 按浏览器隔离，推动设置上云 |

一句话总结：**从「让 AI 替我做」改成「把需求和验收说清楚，让 AI 帮我更好地说出我想说的话」。**

## 4. 验证方式（45 秒）

- **手写假 DOM 结论不可信**——全部验证走 jsdom 真加载页面：12 套回归脚本、292 条断言，结营当天全绿。
- 发布前固定跑 8 项检查（密钥扫描/相对路径/CORS/口令隔离/解析幂等/文档口径…），今天实跑 8/8 PASS。
- 真接口用独立测试口令走全链路：写入→回读→PATCH→DELETE→清理零残留，不碰真实数据。
- 关键功能主人真机验收（手机微信 + 浏览器），不做「应该没问题」的口头结论。

## 5. 平台限制（30 秒，讲清边界才显得真）

- 微信内置浏览器禁止直接下载文件 → `.ics` 做成检测微信 + 引导跳浏览器，口令随链接带过去不断链。
- 免费版 PostgreSQL 无直连 → 走官方 HTTP 网关（PostgREST），不支持嵌套插入 → 拆成主表+子表两次请求。
- localStorage 按浏览器 App 隔离（微信和系统浏览器互不相通）→ 设置正本上云，本机只做缓存。

## 6. 后续优化计划（30 秒收尾）

- 打包 APK / PWA（Day 27 已摸底：卡点在 CORS 白名单和 Blob 下载桥）。
- 首页新手教程（第三方试用者反馈）。
- 数据导出按钮增强 + 到期前（2027-04-07）自动提醒备份。
- 完成率统计等小功能——但**不影响现在的稳定版本**。
